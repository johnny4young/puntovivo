# Puntovivo v1.11.1 — tighter live-data access and a broad hardening pass

## Why this release matters

v1.11.1 closes two ways the live-data channel exposed more than it should.
Before this release, any signed-in cashier could follow every completed sale of
the store as it happened, including totals meant for managers. A request with
no session at all could also learn how many live connections the whole
installation was carrying. Both now require the right session and role.

The same release also carries a broad hardening pass that was merged just
before it was cut. The notes generated for this release did not list that
work, so it is described here: encryption enforcement for the standalone
server, protection against installing an older desktop version, completed
customer price levels, stricter tax handling, and faster, safer backups.

## What changed

### Live data

- The live sales channel checks role and content: kitchen events reach sales
  roles when the kitchen module is on, and completed sales reach managers and
  administrators. A request for data the role may not see is refused before
  anything is sent.
- The live connection status requires a session and counts only the caller's
  store.
- The read-only live view now shows whether the day close was signed, by whom
  and when, using the store's calendar day rather than the phone's. It can also
  be installed on a phone as a secure web app.

### Hardening included in this release

- The standalone server refuses to create or open an unencrypted database
  outside development and test, and it checks the encryption key before
  opening anything.
- An installed desktop app refuses to update to a version older than the one it
  already runs.
- Customer price levels are applied explicitly in sales, POS Touch and
  quotations, frozen on each sale, and checked again before a draft completes.
- Each product line carries one tax kind. Receipts and quotations keep IVA and
  INC apart, and Colombian electronic invoice output is labelled as a local
  draft.
- Backup passphrase protection runs in the background and can be cancelled,
  generated recovery phrases carry 192 bits of randomness, and recovery bundles
  stream to disk with bounded memory while rejecting malformed archives.
- Verifying the audit chain works in bounded steps and was tested at 100,000
  entries.
- Service items keep their identity through imports and exports and can no
  longer enter purchases or inventory orders.
- Desktop data operations require a valid session before anything is saved,
  with a localized way back in.

## Before you use it

- These notes were written on 2026-09-13, after v1.14.2, to replace the
  generated notes this release was published with. For a desktop installation,
  use v1.14.2 or later.
- A standalone server deployment must now provide `PUNTOVIVO_DB_KEY`, a
  64-character hexadecimal key, or it will not start outside development and
  test.
- This release adds five database migrations. Take an encrypted backup before
  upgrading an existing installation.
- There is no Windows installer: the Windows build failed its packaged-app
  check on a Windows file-sync error in the updater, which v1.14.1 fixed.
- Installed desktop registers were not offered this release automatically,
  because the update feed is published only when every desktop build succeeds.
- Production sale is still gated by fiscal certification and physical-hardware
  validation, as the
  [project status](https://github.com/johnny4young/puntovivo/blob/main/docs/PROJECT-STATUS.md)
  describes.

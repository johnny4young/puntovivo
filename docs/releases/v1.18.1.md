# Puntovivo v1.18.1 — A safer desktop server restart during backups and restores

## Why this release matters

v1.18.0 taught the desktop app to restart its built-in server on its own.
v1.18.1 closes a gap in that work: if the server failed while a restore, a
backup or a key rotation had stopped it, the app could start a new server on the
database while its files were being replaced.

The restart logic now runs on the Electron Stagewright host supervisor, a
shared, tested library, instead of code written only for Puntovivo. The
behaviour the cashier sees is the same as in v1.18.0.

## What changed

- While a restore, a backup, a key rotation or the app shutdown owns the
  database, no new server starts. Actions that arrive in that window are refused
  right away instead of waiting on a server that is not there.
- A server that comes back while a restore begins is not handed to the till
  until the restore has finished.
- The app reads the reason a server stopped (out of memory, an uncaught error)
  from the supervisor, so Operations counts each restart under the right cause.
- The startup, memory and main-thread checks that guard every build give each
  measured launch its own copy of the test database. On Windows the third launch
  no longer slows down because the first two filled the shared one.

## Before you use it

- This release has no database migration and no configuration change.
- Building from source needs Node.js 26.13.1 or newer.
- Windows builds are not code-signed yet, so a downloaded update waits for
  **Restart to install update** in the tray menu instead of installing on quit.
- Production sale is still gated by fiscal certification and physical-hardware
  validation, as the
  [project status](https://github.com/johnny4young/puntovivo/blob/main/docs/PROJECT-STATUS.md)
  describes.

# Puntovivo v1.14.2 — restoring the signed macOS desktop build

## Why this release matters

The 1.14 line has not had a complete desktop release yet. v1.14.0 shipped only
the web bundle, and v1.14.1 added the Windows and Linux installers but still had
no macOS build, so neither release refreshed the desktop update feed. The macOS
build stopped at code signing on GitHub's macOS 26.6 build image: the packaging
tool gave the certificate's password where its temporary signing keychain
required the keychain's own password, and that image no longer tolerates the
mistake. The Apple signing certificate itself was never the problem.

v1.14.2 moves desktop packaging to a version of the tool that fixes that step,
so this release is meant to ship a Developer ID signed and notarized macOS build
next to the Windows, Linux and web packages. It adds no new screens and no
database migrations of its own.

## What changed

### A signing step the macOS build image accepts

Desktop packaging now uses electron-builder 26.16.1. When it imports the
Developer ID certificate into its throwaway keychain, it unlocks that keychain
with the keychain's own password, which is what macOS 26.6 requires. A
repository check now reads the installed packaging code and fails continuous
integration if a future update reintroduces the old behavior, instead of leaving
the next release to discover it.

### Packaged app checks that tell noise from failures

Every release launches the packaged app and fails on any unexpected warning or
error it prints. Two harmless macOS messages had been failing that check: the
system spell-check service starting cold the first time text is typed into a
field, and a process-priority message logged while the app quits. Both are now
recognized by their exact text, and every other message still fails the build.

### Packaging details

The new packaging version also bundles a few small runtime dependencies that
earlier packages left out and keeps the Electron and Chromium license files in
the macOS app. Candidate packages built with it passed the packaged-app and
encrypted-recovery checks on Linux, Windows, and macOS Sequoia 15 and Tahoe 26
before this release.

### If you are coming from v1.14.0 or earlier

v1.14.1 fixed Windows installations where restoring a database backup failed at
its first copy and automatic updates could be reported as unavailable. v1.14.0
introduced first-use business ownership: on desktop, a fresh installation opens
a setup screen where you create the business and its owner account, instead of
starting with a generated administrator password. The
[v1.14.0 release](https://github.com/johnny4young/puntovivo/releases/tag/v1.14.0)
lists the rest of that release's changes.

## Before you use it

- Desktop installations last received an automatic update with v1.11.0. The
  v1.11.1, v1.13.0, v1.14.0 and v1.14.1 releases each had a desktop build fail,
  and the update feed is published only when every desktop build succeeds. If
  all of v1.14.2 builds, it is the first update those installations are offered
  since v1.11.0, and it starts with a 10% staged rollout.
- macOS verifies an update's code signature and can install it on quit. Windows
  and Linux packages are not verified that way yet, so there the update
  downloads but installs only when someone restarts into it from the app. The
  Windows installer is not code-signed, and Windows may warn before running it.
- The signing fix can only be exercised by a real release build, because test
  builds are unsigned by design. This release's own macOS build is the first
  end-to-end proof.
- Production sale is still gated by fiscal certification and physical-hardware
  validation, as the
  [project status](https://github.com/johnny4young/puntovivo/blob/main/docs/PROJECT-STATUS.md)
  describes.

# Puntovivo v1.14.4 — v1.14.3 with stricter release checks

## Why this release matters

v1.14.4 contains the same application as v1.14.3. No screen, data, desktop or
server code changed, and there are no database migrations; only version numbers
moved. The release exists because a correction to the release checks was
recorded as a fix, and the release automation publishes a new version for
every fix.

What changed is how a release is verified before it reaches a register, so the
next release that does change the application is held to a stricter standard.

## What changed

### Release checks

- The packaged app check on macOS treats system spell server messages as a
  failure again. v1.14.3 turned the desktop spellchecker off, so those messages
  should never appear; if they do, the spellchecker is back on and the release
  should stop instead of passing them as known noise.
- The release checks now include a test that fails while the curated notes for
  the version being released are missing. v1.11.0 through v1.14.1 and v1.14.3
  were published with only the generated changelog because nothing checked
  that order.
- The v1.14.3 release page now shows its curated notes.

## Before you use it

- Installed registers will be offered v1.14.4 as an update, starting with a 10%
  staged rollout. It changes nothing operators use, so there is no reason to
  hurry the rollout or to restart a register in the middle of a shift for it.
- macOS verifies an update's code signature and can install it on quit. Windows
  and Linux download the update but install it only when someone restarts into
  it from the app. The Windows installer is not code-signed, and Windows may
  warn before running it.
- Production sale is still gated by fiscal certification and physical-hardware
  validation, as the
  [project status](https://github.com/johnny4young/puntovivo/blob/main/docs/PROJECT-STATUS.md)
  describes.

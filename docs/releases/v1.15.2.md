# Puntovivo v1.15.2 — Receipts that fit and printer setup you can verify

## Why this release matters

v1.15.2 is about the printed ticket and the printer behind it. Thermal
receipts were laid out wider than the paper, so long product names and totals
could be cut off on 58 mm and 80 mm rolls. A failed ESC/POS print could also
open a second print through the system dialog, which risked a duplicate copy
once the printer came back. Printer setup accepted an example network address
for a USB printer and showed a success message after a failed test.

This release makes the ticket fit the paper, keeps exactly one print path per
attempt, and makes printer setup tell the truth about what was checked. It
also keeps the cash handed over and the change on every new cash receipt, and
fixes a few setup and desktop session problems found during a full audit.

## What changed

### Receipts that fit the paper

- 58 mm and 80 mm receipts use the printable width of the roll, so long item
  descriptions, totals, cash received and change print in full.
- ESC/POS lines that already fit keep their column alignment; only lines that
  overflow are wrapped.
- Stacked thermal item rows carry their labels, and empty payment rows are no
  longer printed.
- A reprint keeps the paper size of the original receipt and explains it on
  screen. New ESC/POS output uses the paper width configured on the printer.

### Cash received and change

- A completed single-cash sale now stores the amount handed over and the
  change, and new receipts and reprints show both.
- Receipts from earlier versions never invent a cash-received amount.
- A partial payment shows the outstanding balance and asks for explicit
  confirmation.

### Printing without duplicates

- When an ESC/POS print fails, the job stays in the print queue for its normal
  retry and no second print opens through the system dialog.
- An audited reprint prints its own copy. Cancelling the print dialog says that
  nothing printed and that the reprint was still recorded.
- Automatic printing after a sale through a system printer is an explicit
  opt-in, off by default.

### Printer setup

- A network ESC/POS printer requires its real address; the form no longer
  fills in an example address. Direct USB and serial ESC/POS are labelled as
  not available, with guidance to use the system printer driver instead.
- On desktop, you can pick the exact system printer for this computer, refresh
  the list and send a test ticket that records no sale. A missing printer
  fails with a clear message instead of sending the job to another printer.
- A failed connection test is shown as failed, with its reason. Checking a
  system printer registration is labelled as a registration check, not a
  paper test.
- A queued ESC/POS receipt is not marked as printed if the printer is switched
  to the system method; it waits for review in the print queue.

### Setup, language and desktop sessions

- Dark-mode setup screens are readable, the language choice is shared across
  setup, login and the header, and setup progress refreshes immediately.
- The setup readiness check no longer treats missing purchase, order or
  quotation numbering as a blocker; only missing sale numbering blocks it.
- The desktop app keeps its local session renewable after the register sits
  idle, and Quit finishes saving before the app closes.
- The fallback receipt is fully translated.

The project guides now have Spanish versions, and the website has a bilingual
user manual.

## Before you use it

- This update adds database migration 0095, which adds two optional columns
  for cash received and change. Existing sales are not modified.
- If silent printing was on, choose the system printer on each desktop
  computer after updating. Until you do, receipts open the print dialog
  instead of printing silently.
- Physical printer qualification is still pending. These changes were checked
  with PDF output, simulated print queues and macOS, not with a Windows
  thermal printer. Confirm a test ticket on your own printer before a shift.
- Installed registers are offered the update through the staged rollout; let
  a register finish its shift before restarting into it.
- Production sale is still gated by fiscal certification and physical-hardware
  validation, as the
  [project status](https://github.com/johnny4young/puntovivo/blob/main/docs/PROJECT-STATUS.md)
  describes.

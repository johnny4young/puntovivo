# Puntovivo v1.14.1 — store site isolation, Windows data safety and desktop installers

## Why this release matters

v1.14.1 fixes three problems that matter in day-to-day use. In the web app,
signing in to a different store from a browser that still held the previous
session could show and remember the previous store's site. On Windows, several
places that must write data safely to disk failed, including every database
restore. And the release checks that stopped v1.14.0 from publishing desktop
installers now match the new first-use setup, so Windows and Linux installers
are back.

The macOS build still failed at code signing in this release. The signed macOS
build arrived with v1.14.2.

## What changed

### Each store keeps its own site

- Signing in clears the previous identity's cached data before the new one
  appears, and the app trusts a site list only when every site in it belongs to
  the store that signed in.
- Each browser tab sends the site it shows, even when another tab of the same
  store selected a different one.
- A request naming a site that does not belong to the store, or that is
  inactive, now carries no site at all. Before, the server quietly used the
  store's first active site, so a sale or cash session could land on a site
  nobody selected.
- A review of all 116 server operations that accept a site found none that
  accepted another store's site; the only hazard was that silent substitution.

### Windows data safety

- Update history, the protected minimum app version, audit anchors and database
  restores now write safely on Windows. Without this fix, a restore on Windows
  failed at its first copy, and the updater could report automatic updates as
  unavailable.

### Faster search for stores without medicines

- Product lists and search skip pharmacy-only lookups for stores that have no
  medicine records, with identical results.

### Release checks

- The packaged desktop check now completes the first-use setup, signs out,
  signs back in, and fails if the app prints a password or installation code.

## Before you use it

- These notes were written on 2026-09-13, after v1.14.2, to replace the
  generated notes this release was published with. For a desktop installation,
  use v1.14.2 or later.
- An integration that sends a site header for a site outside its store, or for
  an inactive site, now gets the normal site-required errors on site-scoped
  writes instead of a silently chosen site.
- There is no macOS build: signing failed on GitHub's macOS 26.6 build image
  because of the packaging tool, which v1.14.2 fixed.
- The Windows installer is not code-signed, and Windows may warn before running
  it.
- Installed desktop registers were not offered this release automatically,
  because the update feed is published only when every desktop build succeeds.
- Production sale is still gated by fiscal certification and physical-hardware
  validation, as the
  [project status](https://github.com/johnny4young/puntovivo/blob/main/docs/PROJECT-STATUS.md)
  describes.

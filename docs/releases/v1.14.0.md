# Puntovivo v1.14.0 — business-readiness layers and secure first-use ownership

## Why this release matters

v1.14.0 takes the retail core into the rest of a working store. It integrates
twelve reviewed layers that add returns and store credit, promotions and
loyalty redemption, stock counts and replenishment, lot tracing, supplier
payables, restaurant table service and kitchen preparation, reservations and
delivery, workforce scheduling, and operating profiles for pharmacy, hardware
and butcher shops. A new installation also starts differently: the person at the machine
creates the business and its owner account, instead of the software creating a
default administrator with a generated password.

This release was published only as a web bundle. Every desktop build failed
during the release, so no desktop installer or automatic update exists for
v1.14.0.
v1.14.1 and v1.14.2 completed the desktop side.

## What changed

### Starting a new installation

- A new installation asks for the business, location, country and operating
  profile, then the owner's name, email and a strong password.
- On desktop, setup happens in the main window without an installation code. On
  a standalone server, the owner enters a one-time installation code shown in
  the server's startup output, from the same computer; setup is refused from
  remote machines.
- Existing databases are adopted as already owned, with no change to accounts,
  passwords or data.

### Selling and customer value

- Returns work by line and quantity, exchanges link to a replacement sale, and
  store credit can be issued and spent.
- Percentage promotions have an explicit lifecycle and are checked on the
  server at sale time; loyalty points and store credit can pay at checkout.
- An accepted quotation links to its sale, and supplier invoices link to their
  purchases as payables.

### Inventory

- Stores can run blind counts, reconcile exact lot and serial counts, and draft
  replenishment from current cost.
- Lots are traced from purchase through product transformations.

### Restaurants, reservations and delivery

- Table service runs on the ordinary sale engine, with several modifiers per
  order line and approved add-on catalogs per site.
- Kitchen preparation persists with configurable stations and routing.
- Reservations check capacity and overlaps, delivery orders are tracked, and
  signed external orders can be received.

### Operating profiles and people

- A pharmacy profile adds medicine search, prescription evidence, lot custody,
  quarantine and recalls. Controlled medicines stay blocked.
- Hardware and butcher shop profiles shape the catalog and checkout for those
  stores.
- An opt-in customer display shows the sale on a second screen.
- Employment terms, schedules, shift exchanges and time-clock reconciliation are
  managed per site. Administrators get a Colombia-first pre-payroll workspace
  for reviewing calculations.

### Checked before release

- The integration review corrected defects in the new layers before they
  shipped, each with a regression test: refunded tickets offered for delivery
  or counted as revenue, a database migration that dropped return state, a
  price override threshold that changed with the price, unrounded customer
  balance entries, and commands from another site or user replaying a cached
  result.
- A packaged desktop app ships without the developer console, desktop data
  access is authorized by role, and signed-in users receive only the store
  settings fields the app needs.

## Before you use it

- These notes were written on 2026-09-13, after v1.14.2, to replace the
  generated notes this release was published with. For a desktop installation,
  use v1.14.2 or later.
- This release adds 41 database migrations. Take an encrypted backup before
  upgrading an existing installation.
- Treat any startup output that shows the installation code as a credential,
  and keep it out of shared logs, screenshots and support channels.
- The pharmacy profile proves local software controls, not pharmaceutical
  compliance. Country legal review, registry integration, controlled-medicine
  authorization and a supervised store pilot remain outside the software.
- The pre-payroll workspace produces internal review evidence. It is not final
  payroll, electronic payroll or a legal filing.
- The customer display is a local second-screen workflow, not a hardware
  driver, and kitchen preparation does not guarantee delivery to a physical
  kitchen printer or screen.
- Production sale is still gated by fiscal certification and physical-hardware
  validation, as the
  [project status](https://github.com/johnny4young/puntovivo/blob/main/docs/PROJECT-STATUS.md)
  describes.

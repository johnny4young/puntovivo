# Puntovivo v1.17.1 — Literal stock searches and a clean stop for the desktop server

## Why this release matters

v1.17.1 fixes two problems that could give a wrong answer without any warning.

An inventory stock search that contained a percent sign or an underscore
treated them as wildcards. A search for a product code such as `10%` could
match unrelated products, and the filtered count, units and stock value above
the table grew with them.

In the desktop app, closing the app, starting a backup, a restore or a key
rotation could interrupt an action that the built-in server had already
accepted. An owner-password recovery that was still checking the new password,
for example, could lose its answer when the server stopped underneath it.

## What changed

- Inventory stock searches by name, SKU or barcode now match the text exactly
  as typed, including `%`, `_` and `!`. The table, the count and the stock
  value describe the same products, as the catalog search already did.
- When the desktop server stops, it first lets every action it already accepted
  finish and reply, while the database is still open. Only then does it close
  the database and continue with the shutdown, backup, restore or key rotation.
- Actions that arrive after the stop has begun are refused right away instead
  of being sent to a server that is closing.

## Before you use it

- This release has no database migration and no configuration change.
- Windows builds are not code-signed yet, so a downloaded update waits for
  **Restart to install update** in the tray menu instead of installing on quit.
- Production sale is still gated by fiscal certification and physical-hardware
  validation, as the
  [project status](https://github.com/johnny4young/puntovivo/blob/main/docs/PROJECT-STATUS.md)
  describes.

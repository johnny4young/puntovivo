# Puntovivo v1.16.0 — A calmer register and a way back in after a forgotten password

## Why this release matters

v1.16.0 reworks the screens a cashier uses all day and closes a gap that could
lock an owner out for good. The register now has one command bar and one
charge button, asks for the tender before the customer and the tip, and keeps
the finished sale and its receipt in reach. Closing the register fits on one
screen and shows what is still open before you count.

Until now, the sign-in screen had no way back after a forgotten password. An
admin could reset other users, but the only owner of an installation had no
path at all, because the business data is encrypted on that computer and
Puntovivo does not send email. This release adds **Forgot your password?** to
the sign-in screen.

## What changed

### Getting back in after a forgotten password

- **Another admin** can still reset a password from Users, and the sign-in
  screen now says so.
- **Recovery code.** Admins can generate a one-use code from the user menu
  after confirming their current password. The menu marks admins who do not
  have one yet. The code is shown once, can be copied or downloaded, and is
  replaced when a new one is generated.
- **On this computer.** In the desktop app, when the installation has exactly
  one active user, that user is an admin and no recovery code exists, the owner
  can set a new password from the computer that holds the data, without losing
  anything.
- Every reset signs out existing sessions and is recorded in the audit log.

### A faster register

- One command bar and one charge button, with received and change pinned next
  to confirm and the remaining amount shown in a split payment.
- Quick keys suggested from what sold this week, and products with price and
  stock reachable from the command palette.
- Compact cart rows, and the active ticket stays in view.
- The close register dialog fits on one screen, lists suspended sales for
  review, and shows cash movements beside the count on a supervised close. A
  blind close keeps movements out of view and honors its setting.

### Kitchen, tables and touch selling

- Kitchen tickets change colour with age, the board header shows station load
  and connection, and a footer totals what is still to make.
- The tables page opens on a live floor map, and waiters start on a table grid
  with the check and send action kept in reach.
- The touch catalog can be searched and paged, and tiles show site stock and
  the quantity already in the cart.

### Catalog, reports and setup

- Products can be filtered by category, status, low stock and margin, and
  several selected products can be changed at once.
- Day close readiness is a checklist with an action for each open item, and
  the finance pages show fiscal readiness.
- Guided setup counts only required areas as progress, and the settings
  sections stay in a persistent rail.

### Reliability and accessibility

- The desktop app seals its keys with Electron's asynchronous safeStorage API
  ahead of Electron 46, and Windows waits for the operating system to save its
  key on first launch.
- The local cashier is no longer throttled by the global rate limit, and sales
  no longer reseed the whole catalog.
- Header and select buttons keep their visible text in their accessible name,
  roles are translated in the account button, and counts follow the business
  locale.

## Before you use it

- The update adds one database table for recovery codes. It is applied
  automatically the first time the new version starts.
- After running v1.16.0, going back to v1.15.6 or earlier blocks audited
  writes, sales included, until v1.16.0 is installed again. No data is lost.
  The [operations runbook](https://github.com/johnny4young/puntovivo/blob/main/docs/OPERATIONS-RUNBOOKS.md#update-rollback)
  describes the update rollback step.
- Windows builds are not code-signed yet, so a downloaded update waits for
  **Restart to install update** in the tray menu instead of installing on quit.
- Production sale is still gated by fiscal certification and physical-hardware
  validation, as the
  [project status](https://github.com/johnny4young/puntovivo/blob/main/docs/PROJECT-STATUS.md)
  describes.
